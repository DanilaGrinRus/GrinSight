# Одноразовая подпись в 0.4.7A

## Решение

Отправитель объявляет публичный nonce в S1. Выставитель счёта делает то же в I1. Для завершения каждого из этих обменов нужен соответствующий секретный nonce. Он принадлежит одному открытому сеансу платёжного ядра. Новый запуск кошелька, в том числе в другом экземпляре portable, не должен уметь восстановить его из seed, журнала, снимка кошелька или контрольной записи ОС.

Ядро сохраняет публичный Slatepack и состояние операции. Секретный контекст остаётся в памяти и доступен только операции, которая его создала. Перед подписью ядро проверяет ответ контрагента, фиксирует выбор ответа и забирает контекст для однократного использования. Если результат подписи остался неопределённым, повторный вызов не получает контекст. После удачной финализации повтор того же ответа выдаёт уже сохранённую транзакцию. При обычном приёме S1 и при оплате входящего счёта локальный nonce создаётся и используется в рамках одного вызова.

## Что увидит владелец

| Момент блокировки или завершения процесса | При следующем открытии |
|---|---|
| Отправлен S1 или выставлен I1, результат отсутствует | Старый обмен больше нельзя подписать. Проверить состояние платежа перед началом нового обмена. |
| Ответ уже выбран для подписи, готовая транзакция отсутствует | Исход неизвестен. Проверить операцию. Сохранённый резерв остаётся на месте. |
| Готовая транзакция сохранена | Разрешена повторная отправка сохранённых байтов. |

Если закрыть окно или заблокировать кошелёк в ожидании ответа, одноразовый контекст исчезнет. При переходе со старой сборки новые правила распространяются и на незавершённые операции прежнего формата.

## Граница защиты

Даже согласованный откат журнала и guard не возвращает одноразовое право на подпись. Сам откат может остаться незамеченным, а сведения об операции, которой ещё не было в снимке, могут отсутствовать. Правило прекращает повторное использование nonce в обновлённом приложении. Снимок оперативной памяти работающего подписанта и запуск старого бинарника со старыми резервными копиями лежат за этой границей. Восстановление seed в новом профиле по-прежнему требует проверки состояния цепи.

## Проверка

На тестовых кошельках проверены обычная отправка, отправка с поздним резервированием входов и выставление счёта. После восстановления согласованной старой пары файлов повторный запрос завершился до вызова подписи. При двух одновременных одинаковых ответах счётчик подписей равен одному. Новый журнал и его компактный снимок проходят проверку на отсутствие поля с секретным контекстом.

Отдельный процессный тест принудительно завершает платёжное ядро с двумя операциями. При следующем открытии незавершённая операция сохраняет резерв, а завершённая возвращает исходные байты транзакции. Этот тест прошёл и при переходе с прежнего исполняемого файла, который записывал контекст старого формата.

В поставке Windows portable 0.4.7A от 27.11.2026 прошли 85 проверок упакованного приложения. SHA-256 исполняемого файла `27dd210e88fa93068c113d528c680b461951cc63d2249c29f6ffaf1a5dd2d87a`. Платёжные проверки этой доработки выполнены на изолированных кошельках.

# Reproducing the 0.4.7A application packages

Run each command from the checkout of the selected release commit. All four builders read the version from `Source/ui/app/src/lib.rs`. The Windows lab scripts use the configured build caches under `C:\DHW`. Use a new, empty destination for release files.

| Platform | Command | What it checks |
| --- | --- | --- |
| Windows x64 | `powershell -File Source\build-windows-release.ps1 -BaselinePortable <published-0.4.6-portable.exe> -OutputDirectory <new-folder>` | Builds the window and four runtime programs in release mode. Verifies the hash of the old distribution that supplies the unchanged Tor helper and notices. Runs the portable wallet scenario. Builds the per-user Inno installer from the checked portable runtime, compares installed file hashes and tests uninstall. Use a clean Windows account if GrinSight is already installed. |
| Linux x86_64 | `powershell -File Source\build-linux.ps1` in the Windows lab | Builds the same sources under Debian 10 in the dedicated GrinSightBuild WSL distribution. Runs the window scenario there, creates the DEB, RPM and tarball, compares the three extracted payloads, and runs the packaged wallet on Debian 13. Outputs are in `C:\DHW\dist\linux-0.4.7A-<timestamp>`. |
| Android arm64 | `powershell -File Source\build-android.ps1` in the Windows lab | Builds the Rust code for arm64 and x86_64, runs Java tests and checks the arm64 APK signature against the 0.4.6 signer. The first and second starts run on a freshly created x86_64 emulator using the companion APK. A physical arm64 device requires its own acceptance run. The arm64 APK is the distributable artifact. |
| macOS universal | `bash Source/build-macos.sh` on a Mac with Xcode command line tools and rustup | Builds both arm64 and x86_64, checks the architectures of every program, runs the wallet scenario, verifies ad-hoc code signatures and verifies the DMG. Outputs are in `Source/dist-macos`. This script can also run in the manual macOS build workflow with read-only repository permissions. |

The Android application name is `0.4.7A` and its version code is 407. The Android certificate digest is `891600203fa03bc1d3f5e2a8e2c3b6bd60d73bd1246b368984d003d54f54ba0a`, matching the published 0.4.6 developer APK. Keep the signing key on the build machine. Windows packaging uses SHA-256 checks. macOS ad-hoc signing allows the programs to run on Apple silicon and the release is not notarized.

For the additional check of the distributable APK, use a Google APIs image advertising `arm64-v8a` with ARM translation. Run `Source\test-android-apk.ps1 -Apk <arm64-release.apk> -ExpectedAbi arm64-v8a -Evidence <empty-existing-folder>`. The check reads the installed ABI, starts the wallet twice and checks its Android service and native child process. A successful run in this environment covers ARM translation. Record physical Android hardware separately.

When GrinSight is already installed in the Windows account, the setup builder stops before running install/uninstall. For a read-only check, extract the candidate using Innounp 2.71.4 (`innounp -x -d<empty-directory> <setup.exe>`). Run `Source\test-setup-payload.ps1 -ExtractedApp '<empty-directory>\{app}' -Runtime '<checked-portable-runtime>' -SetupExtra '<setup-extra-directory>'`. This verifies the complete file list and SHA-256 of the contents. Record the actual installation test separately.

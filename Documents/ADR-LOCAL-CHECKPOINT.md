# Точка после самостоятельной проверки в 0.4.7A

На новом устройстве основной путь Mainnet начинается на высоте 4 115 520. В поставку входят запись точки (9 391 байт) и выборочное доказательство GSHP1 (8 285 016 байт, SHA-256 `61fcd6a270cb638e77322a1839eb599f128e51a463f26f5ed038e37a2bdc0edc`). Высота и хеш относятся к началу проверки. Текущая вершина и статус платежа определяются отдельно. В Testnet своя выпускная точка. У неё нет встроенного GSHP1.

## Выбор владельца

В настройках открытого кошелька можно выбрать проверку от genesis. Выбор хранится для этого профиля и его сети. Незавершённый проход продолжится после перезапуска. Уже существующие данные автономной проверки также открываются в этом режиме. В обычном режиме сохраняется поддержка собственной точки ранних версий.

Последовательная проверка использует временный журнал заголовков. По достижении пригодной архивной высоты кошелёк строит точку и выбирает 420 образцов для GSHP1 штатным построителем. Он читает заголовки из журнала по высоте. Готовая пара появляется в каталоге данных цепи данного профиля:

```text
history-exports/<main или test>-<высота>-<хеш>/
    checkpoint.json
    history.proof
```

Точка содержит заголовки контекста сложности, пики и путь включения. В отдельном файле находятся свидетельства для проверки выборки до этой точки. Перед публикацией кошелёк читает оба файла с диска и проверяет, что образцы относятся именно к данному заголовку в выбранной сети. Каталог пары публикуется переименованием. После этого кошелёк фиксирует локальную точку и проверенный хвост. С этого момента временный журнал можно удалить. Сбой до фиксации допускает повтор, а повреждение уже опубликованной локальной точки требует восстановления. Временный журнал может занимать около 1,7 ГБ, пока построение продолжается.

Для следующих запусков устройство использует свою проверенную точку и хвост. Когда архивная высота сдвигается, локальная точка может продвинуться. Переданная копия GSHP1 продолжает относиться к той высоте, которая указана в имени её каталога.

Состояние выходов хранится отдельно. Если после смены архивной точки сохранённый снимок выходов расположен ниже начала оставшегося хвоста, при переоткрытии кошельку может понадобиться свежий архив PIBD. Это отдельная загрузка. Время одного повторного запуска зависит от того, какой архив удалось переиспользовать.

## Проверка на другом Windows-компьютере

На исходном устройстве откройте настройки кошелька и сохраните контрольную точку одним файлом `.gshp`. Файл содержит публичную запись точки и проверяемое доказательство GSHP1. Ключи кошелька, список выходов и баланс в него не входят.

На втором устройстве откройте профиль той же сети и выберите импорт точки в настройках. Укажите один файл `.gshp`. Если точка сохранена прежней сборкой, положите `checkpoint.json` и `history.proof` рядом и выберите только `checkpoint.json`. Завершите текущий обмен Slatepack до импорта. При подтверждении кошелёк блокируется и одноразовый сеанс подписи заканчивается. После успешного импорта снова откройте профиль.

Ядро проверяет соответствие сети, высоты, хеша заголовка и выборочного доказательства. Только после успешной проверки оно записывает пару в каталог цепи этого профиля. При следующем открытии проверяется сохранённая пара. Исходные файлы с другого устройства после этого можно убрать. Заголовки после импортированной высоты, состояние и свежесть вершины проверяются как обычно. Происхождение точки остаётся «импортированная» даже при успешном догоне вершины.

При несовместимом файле выбор точки сохраняется прежним. Для уже начатой собственной проверки от genesis или другой явно выбранной точки используйте отдельный профиль. Повторный импорт той же проверенной пары поддерживается.

Для отдельной проверки без запуска профиля передайте portable EXE путь к файлу `.gshp` или к каталогу прежнего двухфайлового экспорта. Пример для PowerShell:

```powershell
& .\GrinSight-0.4.7A-windows-x64-portable.exe --verify-checkpoint main 'D:\Grin checkpoint\Mainnet-4122000.gshp' | Out-Host
$LASTEXITCODE
```

При успехе программа выдаёт высоту, хеш, число проверенных образцов и возвращает 0. Другую сеть, усечённое доказательство или другую точку программа отклоняет. Команда работает без сети и профиля кошелька. На создавшем устройстве основанием служит полная последовательная проверка. На принимающем устройстве проверяются предъявленные образцы. Копирование файлов само по себе не меняет выбор цепи, локальное происхождение точки или статус платежей.

## Восстановление ранних выходов Grin

Прежняя версия могла пропустить принадлежащий кошельку неизрасходованный выход из эпохи до первого хардфорка. При поиске по seed она пробовала только современный способ извлечения данных из rangeproof. Исправление относится к чтению данных кошелька внутри доказательства. Правила проверки блоков и зрелости выхода остаются прежними.

Владельцу уже восстановленного профиля доступен повторный поиск старых выходов в настройках кошелька. Достаточно открыть этот профиль и разрешить полный поиск, который может потребовать скачивания доказательств. При восстановлении в новом профиле проверка обоих форматов для архивных выходов выполняется автоматически. Когда высота создания известна, кошелёк учитывает эпоху соответствующей сети и переходное окно после HF1.

Кошелёк сообщил `at_tip`; высоты заголовков, применённых блоков, кошелька и выбранной публичными нодами вершины совпали. Это зафиксировано через 190,4 с от начала повторного запуска с разблокированием, при опросе раз в 10 с. Журнал проверки от genesis отсутствовал. Тест выводит ход синхронизации и не совершает платежей. Без `--live` выполняется только проверка переноса и повторного открытия.

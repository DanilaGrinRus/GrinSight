# Windows 0.4.7A · локальное восстановление, платёж и глубокая развилка

27 ноября 2026 г., Windows x64 10.0.26300, CPython 3.10.11. Три последовательных прогона существующих интеграционных тестов в отладочной сборке. У каждого свой пустой каталог, новая группа процессов Windows (Job Object) и отдельная тестовая цепь. Зафиксированы все три успешных завершения и отсутствие оставшихся процессов.

| Сценарий | Wall, с | CPU дерева, с | Пиковый commit дерева, байт | Процессов за прогон | Результат |
| --- | ---: | ---: | ---: | ---: | --- |
| Холодное восстановление и платёж — `autonomous_wallet::old_phrase_genesis_restore_and_payment` | 14,3280 | 3,546875 | 37 822 464 | 7 | PASS |
| Развилка ниже архива — `autonomous_genesis_switches_a_heavier_branch_below_the_archive` | 19,5241 | 4,781250 | 11 218 944 | 3 | PASS |
| Прежний сценарий выдачи исторических выходов — `the_wallet_is_given_the_old_outputs` | 16,8654 | 3,828125 | 16 891 904 | 3 | PASS |

**Что входит.** Первый тест намайнит средства на изолированной сети, восстановит плательщика из тестовой фразы и создаст получателю профиль. Два локальных Grin-пира предоставляют заголовки и PIBD, пять локальных HTTPS-источников предоставляют ответы для выбора вершины и проверки времени. Оба экземпляра доходят до высоты 40. Плательщик находит ровно один исторический выход в архиве высоты 20 и платит получателю через ручной Slatepack. Тест сравнивает подписанную транзакцию с полученной нодой, включает её в проверенный блок и проверяет подтверждение у отправителя и баланс получателя. Время включает подготовку тестовой цепи, обработку платежа и выход всех процессов. Парольная функция работает с меньшей тестовой стоимостью. UI, публичные сети и пользовательские кошельки не используются. [Инструкция и условия теста](../Source/chain/fly-chain/tests/AUTONOMOUS-WALLET.md)

Второй тест сначала доходит до вершины 40, затем получает ветку с общим предком на высоте 17 и 32 новыми заголовками. Проверяет новый hash вершины, переключение поколения, сохранность прежнего журнала и отсутствие ошибочного применения прежнего архива после смены ветви. Для новой ветви пир предоставляет только заголовки. Эти 19,5241 с включают подготовку и начальную догонку. Время одной операции переключения отдельно не измерялось.

Третья строка — отдельный тест, существовавший в 0.4.6, запущенный с компонентами 0.4.7A. Он готовит другую фикстуру, проверяет выдачу старых выходов, делает обязательную паузу и ждёт продвижения до высоты 41. Сравнимого исходного бинарника 0.4.6, который выполняет те же два новых сценария, в этом замере нет. Из строк таблицы нельзя вычислить ускорение.

## Методика

Измеритель создаёт пустой Windows Job Object, запускает Rust-тест с приостановленным главным потоком и включает его в группу до первого исполнения пользовательского кода. Дочерние процессы входят в ту же группу. После выхода корневого теста измеритель ждёт, пока счётчик активных процессов станет равным нулю. Он требует ровно одно реально выполненное испытание с указанным именем и успешным результатом. Если Windows запрещает вложенную группу, тест останавливается. Подмена показателей дерева метриками родителя не предусмотрена.

- Wall измеряется монотонными часами от создания процесса до опустошения группы. CPU — сумма времени в пользовательском режиме и ядре, включая уже завершившиеся процессы. [Microsoft, Job Object accounting](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_accounting_information)
- Пик памяти — системный показатель `PeakJobMemoryUsed` (учтённая выделенная память, commit), в байтах. Физическая резидентная RAM и сумма рабочих наборов отдельно не измерялись. Родительский Python и Cargo-сборка в группу не входят. [Microsoft, Job Object memory accounting](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information)
- Холодный старт здесь означает пустые каталоги профилей. Файловый кэш Windows не сбрасывался. На каждый сценарий есть одно наблюдение. Объём переданных байтов, размер профиля, трафик по этапам и производительность на публичных сетях в этом испытании не измерялись.

## Повторение

Нужен 64-разрядный CPython на Windows. Подготовить бинарники по инструкции [кошелька](../Source/chain/fly-chain/tests/AUTONOMOUS-WALLET.md). Для тестов `blocks` и `old` выполнить в `Source/chain/fly-chain` команду `cargo test --locked --offline --features test-net --test blocks --test old --no-run`. Использовать бинарники на исходном месте сборки, поскольку Cargo встраивает путь к `fly-chain.exe`. Имена тестовых EXE и SHA-256 ниже относятся к выполненному запуску. Можно передать существующий короткий временный каталог через `--temp-root`. Каждый запуск создаёт внутри него собственный каталог.

~~~powershell
# Из корня bootstrap-0.4.7A
$bench = 'Source/tools-audit/measure-bootstrap-job.py'
$wallet = 'C:\DHW\dist\bootstrap-047a-headers-target\debug'
$chain = 'C:\DHW\dist\ba47\debug'
$testTmp = 'C:\DHW\dist\ba47\measure-tmp'
python $bench wallet "$wallet\deps\select-f4d085c46f43f3ad.exe" --host "$wallet\fly-paycore-host-test.exe" --temp-root $testTmp
python $bench fork "$chain\deps\blocks-492feb36ced87a9e.exe" --temp-root $testTmp
python $bench old-outputs "$chain\deps\old-7ee6ced1a56ba2a1.exe" --temp-root $testTmp
~~~

Измеритель возвращает одну строку JSON с кодом выхода, результатом, исходными счётчиками и хешами. [Скрипт](../Source/tools-audit/measure-bootstrap-job.py)

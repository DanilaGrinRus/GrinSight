## Что где

| Путь | Что это |
|---|---|
| `paycore/store` | Журнал: кадры с шифрованием и цепочкой хешей, рваный хвост, снимки, страж хвоста, файловый страж `FileGuard`. 18 тестов |
| `paycore/keys` | Пути ключей (ветка экземпляра, приём без состояния, старые), счётчик ветки, поиск своих выходов по rangeproof. 10 тестов |
| `paycore/wallet` | Само ядро `Core`: отправка, приём с черновиком и без состояния, payment proof, invoice, late-lock, статусы, проверка миграции, экспорт трасс; с ред. 0.9 — автодоставка S1 (конверт в одном кадре с операцией, заметки о доставке, поиск операции по ответу) и подпись с привязкой к вершине цепи; с ред. 0.10 — ответ, пришедший сам, проверяется и хранится до решения о подписи; с ред. 0.11 — текст Slatepack, личность на транспорте и книга контактов; с ред. 0.19 — поиск давних выходов (`tests/old.rs`). 45 тестов |
| `paycore/mailbox` | Порт транспорта сообщений: типы и трейт `Mailbox`, без зависимостей. Его реализует транспорт, им пользуются ядро и прокладка |
| `paycore/mailbox-pipe` | Порт `Mailbox` через границу процессов: формат кадров, сторона кошелька `PipeMailbox`, цикл стороны транспорта `serve`. Без сторонних зависимостей. Запуск транспорта с ожиданием готовности (`spawn`) и без него (`spawn_begin`, `Starting`). 9 тестов (с возможностью `stub`) |
| `paycore/pipe-link` | Общее для каналов между процессами: кадры, запуск дочернего процесса без ожидания, один запрос — один ответ в пределах времени. Без зависимостей. 3 теста |
| `paycore/chain-port` | Порт слоя цепи: трейт `ChainFeed` (позиция кошелька → следующий шаг), типы и пределы; с ред. 0.19 — кусок давних выходов. Без зависимостей. 4 теста |
| `paycore/chain-pipe` | Порт цепи через границу процессов: вид сообщений, сторона кошелька `PipeChain`, цикл стороны процесса цепи `serve`. 12 тестов (с возможностью `stub`). Описание трёх крейтов — `paycore/chain-pipe/README.md` |

## Сборка и тесты

Windows: `run-windows-tests.ps1` — ядро (одиннадцать крейтов, включая хост) и процесс цепи (четыре крейта), `run-transport-tests.ps1` — транспорт и адаптер. Оба пишут журнал рядом с собой, ничего не скачивают и в сеть не выходят. Отдельно и только по желанию — два скрипта, которые **выходят в сеть Tor** (без релея, настоящего кошелька и средств): `run-live-tor-test.ps1` запускает один процесс транспорта и поднимает Tor; `run-live-host-test.ps1` собирает `fly-mailbox`, запускает под хостом настоящий транспорт, запечатывает платёж одноразового тестового профиля и пробует опубликовать его на релей, которого нет. Ещё один, `run-live-headers-test.ps1`, **соединяется напрямую, не через Tor, с публичными нодами Grin** обеих сетей и проверяет цепь заголовков от разработческих точек до вершины (ни кошелька, ни средств; ноды видят адрес компьютера как адрес обычного пира); `run-live-state-test.ps1` делает то же и собирает у нод состояние на их архивной точке — несколько тысяч небольших запросов на Mainnet; `run-live-blocks-test.ps1` идёт дальше и применяет блоки от этого состояния до вершины. `run-live-chain-host-test.ps1` запускает под хостом настоящую программу цепи на тестовой сети: одноразовый пустой кошелёк идёт за проверенными блоками до вершины. `run-live-old-test.ps1` (шаг 5.5, без ключей) доводит программу цепи до вершины и читает давние выходы — rangeproof всего непотраченного: около 240 МБ на Mainnet, около 2 ГБ на тестовой сети. `run-live-restore-test.ps1 -Network test|main` восстанавливает одноразовый профиль из фразы, которую спрашивает скрытым вводом, и ждёт конца поиска: фраза не пишется ни в журнал, ни в файл скрипта, ничего не отправляется. Третий, `run-live-relay-test.ps1`, ещё и **публикует на настоящий релей**: платёж между двумя одноразовыми тестовыми профилями идёт через Tor и релей из набора Goblin (по умолчанию `wss://relay.floonet.dev`, другой — параметром `-Relay`); на релей уходят два запечатанных сообщения.


Нужен Rust 1.97 (проверено на нём) и доступ к crates.io при первой сборке. Пути зависимостей относительные, папку можно переносить целиком.

```
cd paycore/store  && cargo test
cd paycore/keys   && cargo test
cd paycore/wallet && cargo test          # около двух минут
cd paycore/wallet && cargo clippy --all-targets
cd paycore/bridge && cargo test
cd paycore/bridge && cargo run --example host   # образец подключения
python models/paycore_model.py --trace
python models/paycore_model_c.py --trace
```

Чтобы тест заново записал трассы: переменная окружения `PAYCORE_TRACE_DIR=<папка>`.

Линты `unwrap_used`, `expect_used`, `panic`, `indexing_slicing`, `arithmetic_side_effects`, `cast_possible_truncation` стоят в `deny`, `unsafe` запрещён — так должно остаться (спецификация, раздел 15).

## Вход в код

Всё внешнее — методы `fly_paycore_wallet::Core` (`paycore/wallet/src/lib.rs`):

| Задача | Методы |
|---|---|
| Создать, открыть, снимок | `create`, `open`, `checkpoint` |
| Факты цепи | `chain_advance`, `chain_rollback`, `chain_reanchor` |
| Отправка | `send_prepare`, `send_prepare_with_proof`, `send_prepare_late`, `send_finalize`, `send_cancel`, `send_broadcast_result` |
| Приём | `receive_draft`, `receive_stateless`, `set_auto_receive`, `draft_abandon`, `drafts_expire` |
| Invoice | `invoice_issue`, `invoice_finalize`, `invoice_pay` |
| Давние выходы (спецификация, 7.19) | `old_search_start`, `old_search`, `old_apply` |
| Статусы и баланс | `send_status`, `incoming_row`, `unrecorded_output_row`, `balance`, `observe_send`, `observe_incoming` |
| Миграция с v0.1 | `migrate::inspect` |

Устройство: любое изменение — событие; событие сначала устойчиво пишется в журнал, потом применяется единственной функцией `State::apply` (`state.rs`); открытие проигрывает те же события. Подпись делается только по квитанции `Sealed` устойчивого кадра. Slate строится типами Grin (`slates.rs`).

## Чего нет

- Сборки и прогона под Android. На Windows тесты проходят (скрипт `run-windows-tests.ps1`); прогон нашёл и закрыл две ошибки: журнал не укорачивался после сбоя и slate с повторяющимся ключом `off` ронял разборщик Grin.
- Зависимости собираются офлайн из `vendor-crates` по `.cargo/config.toml` этой папки; общий `C:\DHW\vendor` не используется.
- Стража на Android Keystore. Страж на DPAPI для Windows есть и проверен на Windows.
- Работающего приложения из двух процессов. Готово и проверено вживую: канал (`paycore/mailbox-pipe`), программа транспорта (`fly-mailbox`), программа-хост (`fly-paycore-host`); платёж между двумя хостами через Tor и настоящий релей проходит. Не сделано: программа цепи отдаёт кошельку блоки от архивной точки (`chain/README.md`), но не ищет давние выходы, не отправляет транзакции и не называет выбранную вершину — статусы остаются предварительными; под продуктовым хостом пустой кошелёк тестовой сети дошёл по проверенным блокам до вершины (`live-chain-host-test-20261122-1558.log`), входящего платежа из блоков ещё никто не видел, так что средства в кошельке появиться ещё не могут; живой платёж шёл на тестовой цепи; сборка двух программ в один каталог для интерфейса; сам интерфейс. Автоподпись выключена, пока слой цепи не называет выбранную вершину (шаг 5.7).
- Самого V (индекс выходов, bitmap, пики) — он в ядре Fly; в журнале для него есть место.
- Подключения к приложению: прокладка `paycore/bridge` готова, но в `grinsight-service` не встроена, а Dart-клиент не компилировался.
- Сверки с моделью исследователя: экспорт трасс есть, схема действий и номера строк статусов не согласованы.
- Испытаний на живой сети.
- Независимого ревью (план — спецификация, раздел 17).
- Упрощения реализации перечислены в `paycore/wallet/README.md`: кадры в JSON, зависимость от всего libwallet вместо тонкого крейта slate, отпечаток slate — SHA-256 байтов.

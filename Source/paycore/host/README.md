# Хост: процесс кошелька (`fly-paycore-host`)

Программа, которую запускает интерфейс. Один процесс — один каталог профиля. Она открывает профиль по паролю, держит платёжное ядро на одном рабочем потоке и запускает для открытого профиля процесс транспорта. Сетевого кода в ней нет.

```
интерфейс (Flutter)
   │  строки JSON-RPC 2.0 по стандартному вводу и выводу
   ▼
fly-paycore-host ── host.*     профиль: создать, восстановить, открыть, закрыть, пароль
   │             └─ paycore.*  → Runner → Bridge → Core   (только пока профиль открыт)
   │  кадры по стандартному вводу и выводу дочернего процесса
   ▼
fly-mailbox (Tor, Nostr; без ключей кошелька)
```

## Запуск

```
fly-paycore-host --profile <каталог> [--guard-dir <каталог>] [--device-key-stdin] [--transport <программа> --relay <адрес>] [--onion <программа>] [--tor-bridges <файл>]
                 [--chain <программа> [--chain-peer <адрес>]...]
```

| Аргумент | Что это |
|---|---|
| `--profile` | каталог профиля; создаётся, если его нет |
| `--guard-dir` | где лежит страж хвоста. По умолчанию `%LOCALAPPDATA%\GrinSightLight\guard` на Windows, `$XDG_STATE_HOME/grinsight-light/guard` или `~/.local/state/grinsight-light/guard` на остальных. Должен быть вне каталога профиля, иначе запуск отклоняется |
| `--device-key-stdin` | (не Windows) первая строка ввода — не запрос, а ключ устройства для стража: ровно `{"jsonrpc":"2.0","method":"host.device_key","params":{"key":"<64 шестнадцатеричные цифры в нижнем регистре>"}}`. Ключ — 32 байта, которые запускающая сторона хранит под ключом устройства (на Android — служба, под ключом Android Keystore). Страж тогда открывается только этим ключом вместе с паролем: профиль, скопированный на другое устройство вместе со стражем, не открывается как свой (`guard` / `foreign`). Пустой `key` — у устройства такого ключа нет: страж привязан только к паролю. Любая другая первая строка — неверный запуск (код 2). Позже `host.device_key` запросом не принимается (K140) |
| `--transport`, `--relay` | программа транспорта (`fly-mailbox`) и адрес релея; только вместе. Без них доставки нет, slate передаются вручную |
| `--onion` | программа Tor для платежей на адрес и приёма на свой адрес (`fly-onion`; спецификация 7.25). Хост запускает её для открытого профиля, передаёт ключ адреса кошелька и сам адрес, папку `onion-<экземпляр>` в профиле; перезапускает после паузы, когда прежнего процесса нет. Без неё методы `paycore.onion.*` отвечают `no_onion`, платёж на адрес передаётся текстом |
| `--tor-bridges` | файл строк мостов Tor, которые выбрал пользователь (спецификация 7.26). Хост читает его при каждом запуске процесса цепи, транспорта сообщений и процесса адреса и передаёт текст в стартовом сообщении; сам строк не разбирает. Нет файла — мостов нет; файл, который не читается, длиннее 60 000 байт или не текст, передаётся словом `unusable`, и процессы не поднимают Tor вовсе. `host.status` → `tor_bridges: {lines, usable}` |
| `--chain` | программа слоя цепи. Без неё о цепи ничего не известно: блоков нет, время не подтверждено, транзакции в сеть не уходят |
| `--chain-peer` | адрес узла или пира для слоя цепи; можно указать несколько раз (до 32). Только вместе с `--chain` |

В аргументах и окружении нет ничего секретного. Неверный запуск — код выхода 2 и одна строка в стандартный поток ошибок; больше туда ничего не пишется. Журнала работы программа не ведёт.

## Разговор с интерфейсом

Одна строка — один запрос JSON-RPC 2.0, одна строка — один ответ, в порядке запросов. Между ответами приходят уведомления `paycore.event` (исходы доставки), у них нет `id`. Строка длиннее 257 КБ не разбирается: ответ `invalid_request`, следующая строка читается как обычно. Пустые строки пропускаются. Конец ввода — блокировка профиля и выход с кодом 0.

Если интерфейс перестал читать, уведомления не копятся без предела: лишние отбрасываются, а перед следующей строкой приходит `host.events_dropped {count}`. Состояние при этом не теряется — его можно спросить заново.

### Методы `host.*`

| Метод | Параметры | Ответ |
|---|---|---|
| `host.status` | — | `profile`: `none` / `locked` / `unlocked`; `network`; `guard_binding` — к чему привязан ключ стража: `os_user` (Windows: этот пользователь на этом компьютере), `device` (ключ устройства вместе с паролем), `password` (только пароль: копия профиля вместе со стражем не будет замечена); `transport`: `configured`, `phase` (`none`, `starting`, `ready`, `down`), `error` (почему процесс транспорта не работает), `problem` (что мешает работающему транспорту: релей недоступен, релей отказал и что он ответил), `starts`; `chain`: те же пять полей о процессе цепи |
| `host.profile.create` | `password`, `network` (`main`, `test`) | `mnemonic` — 24 слова, показываются один раз. Профиль остаётся закрытым |
| `host.profile.restore` | `password`, `network`, `mnemonic` | `{}`. Регистр и лишние пробелы во фразе не важны. В журнал такого профиля сразу записано «искать давние выходы» (спецификация, 7.19): после открытия кошелёк доходит до вершины и читает куски; ход — `paycore.search.status` |
| `host.unlock` | `password`, необязательно `reset_guard` | `guard` (`match`, `caught_up`, `rolled_back`, `missing`), `guard_key` (`existing`, `created`, `reset`), `recovered` |
| `host.lock` | — | `{}`; возвращается, когда рабочий поток, ядро и процесс транспорта завершены |
| `host.profile.mnemonic` | `password` | `mnemonic` |
| `host.profile.change_password` | `password`, `new_password` | `{}` |

Все методы `paycore.*` описаны в `bridge/README.md`; хост передаёт их ядру как есть. Пока профиль закрыт, на любой из них ответ — `locked`.

| Код | Имя | Когда |
|---|---|---|

| −32041 | `no_profile` | профиля в каталоге нет |
| −32042 | `profile_exists` | создание или восстановление поверх существующего профиля |
| −32043 | `wrong_password` | пароль не подошёл или запечатанная часть файла изменена — различить нельзя |
| −32044 | `guard` | ключ стража чужой (`foreign`) или файл ключа повреждён (`damaged`) |
| −32045 | `already_unlocked` | повторное открытие |
| −32046 | `bad_mnemonic` | фраза не проходит проверку |
| −32047 | `no_journal` | файл профиля есть, а журнала нет |
| −32048 | `profile_damaged` | файл профиля не читается как профиль |

## Что лежит на диске

```
<профиль>/profile.json                 файл профиля
<профиль>/wallet-<экземпляр>/          журнал ядра
<профиль>/transport-<экземпляр>/       файлы процесса транспорта (состояние Tor, сохранённые ответы)
<профиль>/chain-<экземпляр>/           файлы процесса цепи (заголовки, состояние); ничего о кошельке
<страж>/<экземпляр>/guard.key, guard-*.dat
```

**Файл профиля.** Seed, корневой ключ журнала, идентификатор экземпляра и ключ обёртки стража — одним блоком под XChaCha20-Poly1305. Ключ блока — scrypt от пароля (N = 2¹⁷, r = 8, p = 1: 128 МБ памяти на попытку). Параметры, соль и сеть записаны открыто и привязаны к блоку: подменить их, не зная пароля, нельзя. Файл, который просит меньше работы, чем 2¹⁵, или больше, чем 2²⁰, не открывается вовсе. Запись — во временный файл, сброс на диск, переименование.

**Порядок создания.** Сначала журнал в каталоге с новым случайным именем, потом файл профиля. Сбой посередине оставляет каталог, на который никто не ссылается; профиля при этом нет, и создание можно повторить.

**Пароль** берётся как есть, байтами UTF-8, от 1 до 1024 байт. Хост не нормализует Юникод и не оценивает стойкость — это дело интерфейса.

## Правила

1. **Закрытый профиль молчит.** Ни один метод ядра не выполняется, пока профиль не открыт паролем.
2. **Существующий профиль не перезаписывается** ни созданием, ни восстановлением.
3. **Пропавший журнал не заменяется пустым.** Если файл профиля есть, а каталога журнала нет, открытие отклоняется; новый кошелёк на его месте не появляется.
4. **Страж не сбрасывается без спроса.** Повреждённый или чужой ключ стража — ошибка `guard`; заменить его можно только явным `reset_guard`, и после этого ядро сообщает `recovered` и блокирует прежние операции для подписи. Исправный ключ `reset_guard` не трогает.
5. **Блокировка заканчивает всё.** `host.lock` и конец ввода возвращаются после того, как рабочий поток остановлен, ядро уничтожено и процесс транспорта завершён.
6. **Кошелёк не ждёт транспорт.** Процесс транспорта запускается без ожидания готовности. Пока он не готов, упал или не запустился: запечатать нельзя (платёж с доставкой отклоняется до резерва), публикация — «занято», входящих нет, а на вопрос о сохранённом ответе никогда не отвечается «его нет». Упавший транспорт запускается снова через 30 секунд, с той же личностью и только после того, как прежний процесс завершён.
7. **Тестовая сеть и тестовая цепь — только в тестовой программе.** Продуктовая программа не принимает сеть `automated` и не открывает профиль с дешёвым выводом ключа.
8. **Кошелёк не ждёт цепь.** Процесс цепи запускается при открытии профиля без ожидания готовности и завершается при блокировке. Пока он не готов, упал, не запустился или отвечает не по форме: состояние цепи «неизвестно», время не подтверждено, выбранной вершины нет, следующий шаг «неизвестен», исход отправки «неизвестен». «Ничего нового» и «принято» за процесс, который этого не сказал, хост не говорит никогда. Упавший процесс запускается снова через 30 секунд.
9. **Слою цепи верят сейчас, а не вчера.** Состояние цепи, число подтверждений, подтверждённое время и выбранная вершина спрашиваются у процесса цепи в момент решения и не запоминаются. «У вершины» засчитывается только слою, у которого есть вершина, выбранная по правилам приёма; без неё состояние — «отстаёт», и ни один статус не поднимается выше предварительного. Число подтверждений 0 не принимается — берётся 10.
10. **Процесс цепи ничего не знает о кошельке.** Ему передаются сеть, хеш генезиса, его каталог, адреса из командной строки; дальше — только позиция кошелька (высота и хеш) и готовые транзакции.

## Чего пока нет

- **Программы цепи.** Хост умеет запускать процесс цепи и говорить с ним (канал — `chain-pipe/README.md`), сама программа — `fly-chain` (`chain/README.md`); в тестах хоста — подставная. Без `--chain` продуктовая программа работает как раньше: о цепи ничего не известно, средства в кошельке появиться не могут.
- **Ожидание на цепи.** Как и с транспортом: запрос к процессу цепи ждёт ответа до 30 секунд на том же потоке, что и запросы интерфейса.
- **Подписи без участия пользователя** — выключена, пока слой цепи не называет выбранную вершину (этап 5.7).
- **Ожидание на транспорте.** Запросы интерфейса и круги доставки идут на одном потоке. Пока он ждёт ответа процесса транспорта (публикация через Tor — до 20 секунд), остальные запросы стоят в очереди. Интерфейс должен вызывать методы асинхронно.
- **`transport.problem` — чужие слова.** В нём может стоять ответ релея. Текст обрезан до 240 печатных символов ASCII; показывать можно, решать по нему ничего нельзя.
- **Смена контактов перезапускает транспорт**, а с ним и подключение к Tor.
- Память ключевой цепочки Grin и буфер разборщика JSON при освобождении не затираются. Пароль, фраза и строки запросов и ответов, которые держит сам хост, затираются.
- На не-Windows ключ стража обёрнут ключом из файла профиля, а не хранилищем системы: профиль, скопированный вместе с каталогом стража, как перенесённый не распознаётся.

## Тесты

```
cargo test --features test-chain
```

Признак `test-chain` собирает вторую программу, `fly-paycore-host-test`: тот же хост с подставной цепью («на вершине, время подтверждено, всё принято»), сетью `automated`, быстрым выводом ключа и возможностью выдать новому профилю средства (без параметра `test` профиль создаётся как в продукте: без позиции и без средств). В продуктовую программу из этого не попадает ничего. Подставной транспорт — `host-mailbox-stub`; «релей» — общий каталог. Подставной процесс цепи — `host-chain-stub`; «цепь» — каталог с блоками, которые кладёт тест.

Тесты запускают настоящие процессы и говорят с ними только строками JSON:

- профиль: создание, неверный пароль, блокировка, смена пароля, повторный показ фразы, два хоста на один профиль;
- восстановление по фразе даёт тот же кошелёк;
- профиль, восстановленный по фразе, находит давние выходы; профиль с новой фразой не ищет, пока не попросят; слой цепи без давних выходов — поиск ждёт и не заканчивается ничем;
- платёж между двумя хостами, у каждого свой процесс транспорта; блокировка завершает транспорт только своего профиля; ни пароль, ни фраза, ни `nsec` не встречаются ни в одном файле;
- транспорт, который молчит, отказывает, не существует, убит снаружи;
- релей отказывает: причина доходит до `host.status` простым текстом, попыток за первые секунды не больше двух, по просьбе пользователя — сразу;
- страж: откат журнала, повреждённый ключ, чужой ключ, пропавший страж, пропавший журнал;
- цепь: два хоста, у каждого свой процесс цепи и свой процесс транспорта. Кошелёк получает точку отсчёта, находит свои выходы в блоках, платит; транзакция уходит процессу цепи байт в байт (исходы «неизвестно», «отказ», «принято» записаны как есть); блок подтверждает платёж обоим; реорганизация снимает подтверждение, пока транзакция не попадёт в блок снова; пока слой говорит «не знаю», ничего не меняется; блокировка завершает процесс цепи только своего профиля; после разблокировки кошелёк догоняет;
- процесс цепи, который молчит, отказывает, отвечает не по форме, не существует, убит снаружи;
- что видит ядро: «у вершины» только при выбранной вершине, понижение оценки действует сразу, 0 подтверждений не принимается;
- продуктовая программа: негодные строки, слишком длинная строка, неверные аргументы; с программой цепи идёт за ней.

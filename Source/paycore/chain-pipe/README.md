# Канал цепи: `chain-port`, `chain-pipe`, `pipe-link`

Процесс кошелька не содержит сетевого кода. Слой цепи — пиры, заголовки, доказательства, блоки — работает отдельным процессом; кошелёк говорит с ним по его стандартному вводу и выводу. Здесь три крейта:

| Крейт | Что в нём |
|---|---|
| `chain-port` | сам порт: трейт `ChainFeed`, типы шагов и пределы. Без зависимостей |
| `chain-pipe` | порт через границу процесса: `PipeChain` — сторона кошелька, `serve` — сторона процесса цепи, `wire` — вид сообщений |
| `pipe-link` | общее для каналов: кадры, запуск дочернего процесса без ожидания, один запрос — один ответ в пределах времени. Без зависимостей |

## Порт

Кошелёк сообщает, где он стоит: высота и хеш заголовка последнего применённого блока (или «нигде»). Слой цепи отвечает одним шагом:

| Шаг | Смысл |
|---|---|
| `Nothing` | кошелёк стоит на вершине, которую слой проверил |
| `Block` | факты блока ровно над позицией: выходы (commitment, rangeproof, позиция в наборе, признак coinbase), потраченные commitments, кернелы, изменение V |
| `Rollback { to }` | позиция кошелька не на цепи слоя: вернуться на высоту `to`, строго ниже позиции |
| `Reanchor(tip)` | начать заново с этой точки: кошелёк пуст, слишком глубоко ушёл или стоит ниже точки отсчёта слоя |
| ошибка `Unknown` | слой не может ответить. Это не «ничего нового», не откат и не отказ |

Ещё три вызова: `status` — оценка слоя (уровень `Unknown` / `Behind` / `AtTip`, его вершина, выбранная вершина, подтверждённое время, `k_conf`, подлинны ли rangeproof) или «нет ответа»; `post` — отдать готовую транзакцию (`Accepted`, `Rejected`, `Unknown`); `problem` — слова о том, что мешает, только для показа.

Пятый вызов, `old_outputs(номер)` — кусок давних выходов (спецификация, 7.19): что непотрачено в одном участке дерева выходов среди того, что старше блоков слоя. В ответе выходы, блок `at`, после которого они непотрачены, высота `before`, до которой кусок полон, номер следующего куска или «это последний», и число кусков. Слой, который дать кусок не может — сейчас или вообще, — отвечает `Unknown`; так отвечает и реализация по умолчанию. `Unknown` — не «пустой кусок». `OldOutputs::answers(номер)` говорит, годится ли кусок как ответ на вопрос о куске с этим номером; обе стороны канала спрашивают это до передачи и после чтения.

Пределы блока: 2 000 выходов, 40 000 входов, 13 400 кернелов, rangeproof до 675 байт, изменение V до 1 МБ; транзакция до 2 МБ; кусок давних выходов — до 2 048 выходов. Блок и кусок сверх пределов не кодируются и не читаются.

## Правила стороны кошелька (`PipeChain`)

1. **Не говорит больше, чем знает.** Процесс молчит дольше отведённого времени, умер, ответил не тем или не по форме — статуса нет, шаг «неизвестен», отправка «неизвестна». Никогда «ничего нового» и никогда «принято».
2. **Не верит форме ответа на слово.** Блок должен быть ровно над посланной позицией; шаг назад — строго ниже неё; «ничего нового» возможно только для кошелька с позицией. Ответ, который не подходит к вопросу, не применяется, и разговор с этим процессом заканчивается (хост запустит новый).
3. **Счётчики проверяются до выделения памяти**, каждый байт ответа должен быть учтён.
4. **О кошельке через канал уходит только позиция и готовая транзакция.** Запросов с commitments, ключами или суммами в протоколе нет.

## Вид сообщений

Кадр: длина (4 байта, от младшего), метка (1 байт), содержимое; не больше 4 МБ. Первым идёт `HELLO` с настройкой: версия (4 с ред. 0.32: в конце статуса добавлен байт «условно»; процессы разных версий друг с другом не начинают), сеть (1 — основная, 2 — тестовая, 3 — автоматические тесты), хеш генезиса, каталог данных, список пиров, предел времени запуска. Ответ — `READY` с версией или `FAILED` с причиной.

| Запрос | Ответы |
|---|---|
| `STATUS` 0x01 | `STATUS_IS` 0x81, `UNKNOWN` 0x8F |
| `NEXT` 0x02 + позиция | `NOTHING` 0x82, `BLOCK` 0x83, `ROLLBACK` 0x84, `REANCHOR` 0x85, `UNKNOWN` 0x8F |
| `POST` 0x03 + транзакция | `POSTED` 0x86 |
| `PROBLEM` 0x04 | `TEXT` 0x87, `NO_PROBLEM` 0x88 |
| `OLD` 0x05 + номер куска | `OLD_ARE` 0x89 (номер куска, блок, `before`, число кусков, есть ли следующий, выходы), `UNKNOWN` 0x8F |

Процесс цепи завершается, когда закрывается его ввод; непонятный запрос заканчивает разговор.

## Тесты

`cargo test --features stub` в `chain-pipe` — 12 тестов: канал в памяти (каждый вид ответа туда и обратно; точность и пределы вида сообщений; мёртвый и молчащий процесс; ответы, которые не подходят к вопросу; процесс, который не стартует; сервер и непонятные запросы; давние выходы — куски туда и обратно, вид сообщения, кусок не к вопросу) и три с настоящим подставным процессом (`chain-stub`: «цепь» — каталог с блоками). `pipe-link` — 3 теста кадров и разбора, `chain-port` — 4 теста: пределы блока, текст о помехе, кусок давних выходов как ответ на вопрос, слой без давних выходов.

Признак `stub` собирает подставной процесс цепи для тестов; в продукт он не входит.

# 0.4.7A: последовательная проверка истории от genesis

## Граница доверия

`genesis::GenesisVerifier` начинает с полного заголовка genesis выбранной сети из той же копии `grin_core`, что использует кошелёк. Для входного файла требуется полное равенство полей первого заголовка. Один хеш в Grin вычисляется по PoW-решению и для этого сравнения недостаточен.

За каждый принятый заголовок можно утверждать следующее: он продолжает проверенный префикс именно этой сети, ссылается на своего предшественника и коммитит к PMMR всех предыдущих заголовков; заявленная прибавка работы положительна, достигнута PoW и равна требуемой прибавке. До HF4 проверяется и secondary scaling. Эти утверждения условны на правила консенсуса данной версии узла и обычные криптографические предпосылки Grin. Вероятностной выборки здесь нет.

Текущий час передаёт вызывающий код. При превышении future time limit проверка откладывается. Свежесть вершины, выбор между валидными префиксами, проверка состояния PIBD и история транзакций имеют собственные проверки. Равенство полей сохранённой точки и корректность пути PMMR сами по себе полную проверку её прошлого не восстанавливают. Для нового устройства исходным свидетельством снова служит проверенный от genesis префикс либо отдельно обоснованный механизм.

## Какие правила исполняются

| Проверка | Источник правила |
|---|---|
| Обе сети и exact genesis | `grin_core::genesis::{genesis_main,genesis_test}` |
| Версия, допустимый граф, PoW, максимальный глобальный вес, future time limit | `grin_core::core::block::UntrustedBlockHeader`, `grin_core::pow::verify_size` |
| Высота, время, рост количеств выходов и кернелов, предел веса блока, фактически достигнутая работа, target и scaling | `grin_chain::pipe::validate_header` |
| Работа одного заголовка и порядок окна | `grin_chain::store::DifficultyIter` |
| DMA, padding в начале цепи, WTEMA | `grin_core::consensus::next_difficulty`, `global::difficulty_data_to_vector` |
| Корень header PMMR для каждого `prev_root` | те же `Peaks` и позиционное хеширование, что в штатном `HeaderChain` |
| Взаимодействие с обычной контрольной точкой | `GenesisVerifier::record` пишет через `checkpoint::write`; тот повторно читает и сверяет точку |

Реализация 0.4.6 `fly-history` принимала поток с нулевой высоты без полной сверки первого заголовка с genesis. В ней проверка WTEMA начиналась, когда оба предшественника уже имели версию 5. В 0.4.7A правило выбирается по высоте *нового* заголовка, в том числе на первых двух высотах новой эпохи. Для расчёта DMA хранятся последние 61 сводка сложности. Для проверки следующего корня и вывода точки сохраняются три заголовка и логарифмические фронтиры PMMR. Рабочая память библиотеки ограничена; хранение, возобновление и откат журнала обслуживает вызывающий процесс. Точка формата кошелька может быть выдана только после накопления трёх проверенных WTEMA-заголовков.

## Воспроизведение

Из `Source/chain/headers`:

```text
cargo test --offline --locked --features testkit,history-proof
cargo clippy --offline --locked --lib --features history-proof
cargo run --offline --locked --release --bin fly-history -- tests/mainnet/first-4100-headers.bin --network main
```

Формат файла: для каждого заголовка сначала длина u16 big-endian, затем каноническая полная сериализация. CLI отвергает пустой файл, превышение предела 1024 байт, обрыв внутри длины или заголовка, неподходящую сеть и любую ошибку проверки. `--checkpoint <новый-файл>` выдаёт запись только после проверки всего ввода. При первой ошибке `push` остаётся на предыдущем заголовке и сохраняет все входы DAA и PMMR.

Проверены настоящий префикс 0…4099 mainnet, несовпадение genesis двух сетей, изменение полей genesis при том же PoW-хеше, испорченные версия/корень/PoW, верхняя граница времени, структура кадра и продолжение после отказа. Тестовая цепь AutomatedTesting майнится от genesis штатным PoW через все пять эпох. На высотах 11, 12, 13 проверяется отклонение неправильной заявленной работы при наличии самостоятельно валидного PoW. На высоте 18 проверяется выдача точки, её повторное открытие штатным читателем, равенство выбранного хеша и пиков. Детерминированный корпус всех однобитовых изменений первого преемника mainnet проходит через настоящий декодер и верификатор; изменённые заголовки оставляют проверяемую цепь на genesis, затем исходный блок принимается. Фикстура реальных первых 4100 блоков охватывает только первую эпоху.

## Замер Windows x64

Собрать релизный `fly-history` из коммита `be41231cd7ab73f158f8219e3fc44d1c3fe781f6`, сохранить бинарник отдельно и собрать такой же CLI из 0.4.7A. Запустить `python tests/measure_history.py <старый-exe> <новый-exe> tests/mainnet/first-4100-headers.bin`. Скрипт делает прогрев, затем пять чередующихся запусков каждого варианта, сопоставляет результаты и получает CPU и пик working set через Windows API. Хеши, все десять измерений и итоговый заголовок сохранены в `tests/mainnet/verification-047a-benchmark.json`.

| Медиана последовательной проверки 1 648 750 байт | 0.4.6 | 0.4.7A |
|---|---:|---:|
| Полное время процесса | 157,511 мс | 154,842 мс |
| CPU | 140,625 мс | 140,625 мс |
| Пиковый working set | 6 008 832 байта | 5 636 096 байт |
| Сетевой трафик, запись состояния | 0 байт | 0 байт |

Замер описывает локальную валидацию раннего префикса с тёплым файловым кэшем. Данные полной исторической прокачки, полной переорганизации и Android по этому эксперименту неизвестны. Отчёт о 4 123 322 заголовках, сохранённый для прежней версии, не является результатом новой сборки.
